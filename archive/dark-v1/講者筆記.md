## 03. Autoregressive inference

每次 forward 產生下一個 token 的分布

這裡使用標準自回歸文字生成路徑，不討論訓練的 backward。LM head 將 hidden state 投影至 vocabulary logits。temperature、top-k、top-p 等控制抽樣。EOS、stop string 或長度上限決定何時結束。

## 05. Serve 不同模型，改動在哪裡？

Checkpoint、架構與硬體 backend 是不同層次的變更

## 06. Continuous batching

每輪調度重新組合仍在執行的 requests

圖中的 dynamic batching 是整批收集後執行的示意名稱。Continuous batching 在 iteration 邊界讓完成者離開、新 request 加入，減少等待最慢序列的空槽。圖本身沒有表示 chunked prefill 或 prefill/decode 混合的完整細節。

- [Inside vLLM](https://vllm-project.github.io/2025/09/05/anatomy-of-vllm.html)

## 07. PagedAttention

Logical blocks 對應非連續的 physical KV blocks

PagedAttention 解決 KV 的配置與存取問題，並不改變模型的 attention 定義。按 block 分配減少大型連續預留造成的浪費，末頁仍可能有內部碎片。Prefix caching 是利用這套配置重用前綴計算的另一層策略。GIF 自動循環，PDF 只會保留其中一幀。

- [vLLM PagedAttention](https://blog.vllm.ai/2023/06/20/vllm.html)

## 08. 每一輪 scheduler 做什麼？

以 token budget 與 cache 可用量決定本輪工作

Chunked prefill 的 chunk 是 serving 排程單位，後面的 GDN chunkwise 是數值演算法，兩者不可混用。切小 prefill chunk 可能減少 decode 被拖慢的時間，但增加排程或 launch overhead。實際取捨要測量。

- [Inside vLLM](https://vllm-project.github.io/2025/09/05/anatomy-of-vllm.html)

## 10. Prefill 與 decode

相同 layers，不同 token 維度與歷史資料存取

演示刻意用 4 個 prompt tokens 與 3 個 output tokens。Prefill 以因果遮罩處理多個已知位置，並寫入各層 K/V。第一個 output 由 prompt 最後位置產生；第二個 output 的 forward 輸入是第一個 output。最後抽樣出的 token 若立刻結束，未必再被 forward，因此不必已存在 KV 中。

- [Qwen3 Technical Report](https://arxiv.org/abs/2505.09388)
- [Inside vLLM](https://vllm-project.github.io/2025/09/05/anatomy-of-vllm.html)

## 11. Decode 如何使用 KV cache

每層只新增目前位置的 K/V，再讀取歷史 K/V

Attention 是 softmax(q K^T / sqrt(d)) V，這裡省略 mask、head indexing 與實作融合。每個 layer 有自己的 cache。快取的是歷史 K/V，不是歷史 Q，也不是完整的模型答案。GQA 多個 query heads 共用較少 KV heads。

- [Qwen3 Technical Report](https://arxiv.org/abs/2505.09388)

## 12. Prefill 與 decode 的效能形狀

瓶頸取決於 batch、context、kernel 與精度

Full attention prefill 的注意力計算對序列長度約二次成長，但 FlashAttention 不需將完整分數矩陣寫回 HBM。不能因此說所有 prefill 都 compute-bound、所有 decode 都 memory-bound；需 profiler 才能確認。MoE、長 context、大 batch 都可能改變瓶頸。

- [Inside vLLM](https://vllm-project.github.io/2025/09/05/anatomy-of-vllm.html)

## 13. Dense 與 MoE 的差別

## 17. GDN 的一次 state update

## 33. 由 RPS 換算服務人數

在穩定系統與一致邊界下使用平均值

Little’s Law C=X R 適用穩定系統，量測窗及 arrival/departure 範圍須一致。Closed user population、每人最多一筆 outstanding、無平行 tool fan-out 時，U=X(R+Z)。若40秒已是送出到送出的週期，U=X×40，不要再加R。全體用戶人口=active users/peak active fraction。不可把goodput率搭配所有requests的平均延遲直接套Little’s Law。

## 35. 附錄 A：測試設定與量測窗

可重現性比單一最高 tok/s 更有用

固定 num_prompts 可以比較樣本，但高 concurrency 需足夠輪次。固定時間方便觀察 open-loop queue buildup，低 RPS 時延長測試以增加 tail 樣本。最少數百筆不代表足以穩健估計 p99，應報告樣本數與重複波動。
